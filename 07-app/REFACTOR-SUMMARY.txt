KEY PROBLEMS FIXED
================================================================================

PROBLEM 1: Global Object Mutability
  BEFORE: app.currentTeacher = newTeacher (no observers)
  AFTER:  GuitarApp.setCurrentTeacher(newTeacher) (triggers "teacher:changed")

PROBLEM 2: No Change Notifications
  BEFORE: Modules couldn't know when teacher changed
  AFTER:  GuitarApp.onTeacherChanged(callback) subscribes to all changes

PROBLEM 3: Uncontrolled State Access
  BEFORE: Any code could mutate app directly
  AFTER:  AppState object with getters/setters + event emission

================================================================================
NEW API METHODS
================================================================================

Reading State (Safe, No Side Effects):
  GuitarApp.getAppState()              → Get current state snapshot
  GuitarApp.app.currentTeacherId       → Read current teacher ID (legacy)
  GuitarApp.app.currentTeacher         → Read current teacher object (legacy)

Mutating State (Always Triggers Events):
  GuitarApp.setCurrentTeacher(teacher) → Change current teacher

Subscribing to Changes (Core New Feature):
  GuitarApp.onTeacherChanged(callback)    → Subscribe to changes
  GuitarApp.onceTeacherChanged(callback)  → Subscribe once, auto-unsub
  GuitarApp.offTeacherChanged(callback)   → Unsubscribe

Internal/Advanced (Usually Not Needed):
  GuitarApp.appEvents                     → Direct EventEmitter access
  GuitarApp.appState                      → Direct state object access

================================================================================
EVENT SYSTEM
================================================================================

EVENT: "teacher:changed"
WHEN:  Fired whenever setCurrentTeacher() is called
PAYLOAD:
  {
    teacher: { id, name, voice },    // New teacher object
    teacherId: "T1",                  // New teacher ID
    previousTeacherId: "T1",          // Previous teacher ID
    timestamp: 1693584321000          // Unix timestamp
  }

USAGE EXAMPLE:
  GuitarApp.onTeacherChanged(function(event) {
    console.log("Teacher changed from", event.previousTeacherId, "to", event.teacherId);
    updateUI(event.teacher);
  });

BEFORE & AFTER COMPARISON
================================================================================

OLD CODE (Original app.js, lines 91-100):
────────────────────────────────────────────────────────────────────────────
function setCurrentTeacher(teacher) {
  const normalized = normalizeTeacherProfile(teacher);
  app.currentTeacher = normalized;
  app.currentTeacherId = normalized.id || "T1";
  if (global.__APP__ && global.__APP__.app) {
    global.__APP__.app.currentTeacher = normalized;
    global.__APP__.app.currentTeacherId = app.currentTeacherId;
  }
  return normalized;
}

// Problem: No way for other modules to know teacher changed


NEW CODE (Refactored):
────────────────────────────────────────────────────────────────────────────
function setCurrentTeacher(teacher) {
  return appState.setTeacher(teacher);
  // Automatically emits: teacher:changed event
}

// In appState.setTeacher() (inside):
setTeacher: function (teacher) {
  const normalized = normalizeTeacherProfile(teacher);
  const oldTeacherId = this._state.currentTeacherId;

  this._state.currentTeacher = normalized;
  this._state.currentTeacherId = normalized.id || "T1";

  // Sync with legacy global.__APP__
  if (global.__APP__ && global.__APP__.app) {
    global.__APP__.app.currentTeacher = normalized;
    global.__APP__.app.currentTeacherId = this._state.currentTeacherId;
  }

  // *** NEW: Emit event so all listeners are notified ***
  stateEmitter.emit("teacher:changed", {
    teacher: normalized,
    teacherId: this._state.currentTeacherId,
    previousTeacherId: oldTeacherId,
    timestamp: Date.now()
  });

  return normalized;
}

PERFORMANCE CHARACTERISTICS
================================================================================

Memory:        ~2KB for EventEmitter + state object
CPU Impact:    Negligible (synchronous event dispatch)

Cleanup:       Automatic via returned unsubscribe function
No Leaks:      Listeners properly removed on unsubscribe

COMMON PATTERNS
================================================================================

Pattern 1: React to Changes
  GuitarApp.onTeacherChanged(function(event) {
    updateUI(event.teacher);
  });

Pattern 2: One-Time Listener
  GuitarApp.onceTeacherChanged(function(event) {
    console.log("First teacher:", event.teacher.name);
  });

Pattern 3: Get Current State
  const state = GuitarApp.getAppState();
  console.log(state.currentTeacherId);

Pattern 4: Cleanup
  const unsub = GuitarApp.onTeacherChanged(callback);
  unsub(); // Unsubscribe when done

Pattern 5: Multiple Listeners
  GuitarApp.onTeacherChanged(logChange);
  GuitarApp.onTeacherChanged(updateUI);
  GuitarApp.onTeacherChanged(syncDatabase);
  // All fire on change
